# 1️⃣1️⃣ What is never?

The `never` type represents values that will never exist.
It is used for functions that never return normally.

**Common Scenarios:**

- 1. Function throws an error

- 2. Function has infinite loop

- 3. Exhaustive type checking

**Example:**

```c
function error(message: string): never {
  throw new Error(message);
}
```

**Another Example:**

```c
function infinite(): never {
  while (true) {}
}
```

**Real-World Usage (Exhaustiveness Check):**

```c
type Shape = { type: "circle" } | { type: "square" };

function assertNever(x: never): never {
  throw new Error("Unexpected object");
}

function area(shape: Shape) {
  switch (shape.type) {
    case "circle":
      return 1;
    case "square":
      return 2;
    default:
      return assertNever(shape); // Compile-time safety
  }
}
```

📌 Difference from void:

- `void` → function finishes but returns nothing

- `never` → function never finishes

# 1️⃣2️⃣ What are union types?

Union types allow a variable to be one of several types.

**Syntax:**

```c
type ID = number | string;
```

**Example:**

```c
let id: number | string;

id = 101;
id = "A101";
```

**Real-World Example:**

```c
function printId(id: number | string) {
  if (typeof id === "string") {
    console.log(id.toUpperCase());
  } else {
    console.log(id.toFixed(2));
  }
}
```

📌 Union types require type narrowing before use

# 1️⃣3️⃣ What are intersection types?

Intersection types combine multiple types into one.
The resulting type must satisfy all combined types.

**Syntax:**

```c
type A = { a: number };
type B = { b: string };
type C = A & B;
```

**Example:**

```c
const obj: C = {
  a: 10,
  b: "hello",
};
```

**Real-World Use Case:**

```c
type User = {
  id: number;
};

type Admin = {
  role: "admin";
};

type AdminUser = User & Admin;
```

📌 Intersection types are commonly used for:

- Role-based access

- Extending models

- Combining API responses

# 1️⃣4️⃣ What is an enum?

An `enum` is a way to define a set of named constants.

**Example:**

```c
enum Role {
  Admin,
  User,
}
```

**Usage:**

```c
function checkRole(role: Role) {
  if (role === Role.Admin) {
    console.log("Admin Access");
  }
}
```

**Compiled JavaScript:**

```c
var Role;
(function (Role) {
  Role[Role["Admin"] = 0] = "Admin";
  Role[Role["User"] = 1] = "User";
})(Role || (Role = {}));
```

**Types of Enums:**

- Numeric enum (default)

- String enum

```c
enum Status {
  Success = "SUCCESS",
  Error = "ERROR",
}
```

📌 String enums are preferred in APIs

# 1️⃣5️⃣ Difference between `null` and `undefined`?

`undefined`

- Variable declared but not assigned

- Default value of variables & function returns

```c
let x;
console.log(x); // undefined
```

`null`

- Explicitly assigned empty value

- Intentional absence

```c
let y: string | null = null;
```

**Comparison:**
| Feature | undefined | null |
| ------------ | --------------- | ------------------- |
| Assigned by | JS engine | Developer |
| Meaning | Not yet defined | Intentionally empty |
| Common usage | Missing values | Clearing values |

📌 In TypeScript with `strictNullChecks`, both must be handled explicitly.

# 1️⃣6️⃣ What is an interface?

An `interface` defines the shape of an object and enforces structure.

**Example:**

```c
interface User {
  name: string;
  age: number;
}
```

**Usage:**

```c
const user: User = {
  name: "John",
  age: 30,
};
```

**Why interfaces are important:**

- Contract enforcement

- Readable code

- Better tooling support

📌 Interfaces are heavily used in **APIs, models, DTOs**

# 1️⃣7️⃣ Interface vs Type?

**Key Differences:**
| Feature | Interface | Type |
| ------------------- | ----------------- | ----- |
| Extensible | ✅ Yes (`extends`) | ❌ No |
| Declaration merging | ✅ Yes | ❌ No |
| Unions | ❌ No | ✅ Yes |
| Intersections | ❌ Limited | ✅ Yes |

**Example:**

```c
interface A {
  a: number;
}

interface A {
  b: string;
}
// merged automatically
```

```c
type B = number | string;
```

**📌 Rule of thumb:**

- Use `interface` for objects

- Use `type` for unions & complex types

# 1️⃣8️⃣ What is optional property?

Optional properties may or may not exist.

**Syntax:**
interface User {
name: string;
age?: number;
}

**Usage:**

```c
const u1: User = { name: "Alice" };
const u2: User = { name: "Bob", age: 25 };
```

**Real-World Example:**

- PATCH APIs

- Partial updates

- Optional request fields

📌 Access with optional chaining:

```c
user.age?.toFixed();
```

# 1️⃣9️⃣ What is readonly?

`readonly` prevents modification after initialization.

**Example:**

```c
interface Config {
  readonly id: number;
}
```

**Usage:**

```c
const config: Config = { id: 1 };
config.id = 2; // ❌ Error
```

**Benefits:**

- Prevents accidental mutation

- Improves immutability

- Safer state management

📌 Widely used in Redux, DTOs, APIs

# 2️⃣0️⃣ What is a tuple?

A tuple is a fixed-length array with fixed types at specific positions.

**Example:**

```c
let user: [string, number] = ["John", 30];
```

**Invalid:**

```c
user = [30, "John"]; // ❌
```

**Real-World Example:**

```c
type ApiResponse = [number, string];
```

📌 Use tuples when order and length matter
