# 3️⃣1️⃣ What are function overloads?

Function overloads allow you to define multiple function signatures for the same function, while having a single implementation.

**Why needed?**

JavaScript allows flexible arguments, but TypeScript needs strict typing.

**Example:**

```c
function add(a: number, b: number): number;
function add(a: string, b: string): string;

function add(a: any, b: any) {
  return a + b;
}
```

**Usage:**

```c
add(1, 2);        // number
add("a", "b");   // string
add(1, "b");     // ❌ compile-time error
```

📌 Overloads define what is allowed, implementation handles how.

# 3️⃣2️⃣ What is structural typing?

TypeScript uses structural typing, meaning types are compatible based on shape, not name.

**Example:**

```c
interface User {
  name: string;
}

const person = { name: "Alice", age: 30 };

const user: User = person; // ✅
```

**Why?**

- Flexible

- Matches JavaScript’s dynamic nature

- Enables duck typing

📌 “If it looks like a duck, it is a duck.”

# 3️⃣3️⃣ What is declaration merging?

Declaration merging allows **multiple declarations with the same name** to be merged into one.

**Example:**

```c
interface User {
  name: string;
}

interface User {
  age: number;
}
```

**Result:**

```c
interface User {
  name: string;
  age: number;
}
```

**Where used?**

- Library augmentation

- Extending third-party types

- Global typings

📌 Works with:

- Interfaces

- Namespaces

❌ Does not work with type.

# 3️⃣4️⃣ What is namespace?

Namespaces group related code under a **single global scope**.

**Example:**

```c
namespace MathUtils {
  export function add(a: number, b: number) {
    return a + b;
  }
}

MathUtils.add(2, 3);
```

**Why less used today?**

- ES modules `(import/export)` replaced them

- Namespaces are mostly legacy

📌 Still seen in old TS codebases and `.d.ts` files.

# 3️⃣5️⃣ What is a module?

A module is any file that uses `import` or `export`.

**Example:**

```c
export function greet(name: string) {
  return `Hello ${name}`;
}
```

```c
import { greet } from "./greet";
```

**Benefits:**

- Encapsulation

- Dependency management

- Tree shaking

- Cleaner architecture

📌 Modern TypeScript always uses modules.

# 3️⃣6️⃣ What is `tsconfig.json`?

`tsconfig.json` configures how TypeScript compiles your project.

**Example:**

```c
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "CommonJS",
    "strict": true
  }
}
```

**Controls:**

- Output JavaScript version

- Module system

- Strictness

- File inclusion

📌 Acts as TypeScript project blueprint.

# 3️⃣7️⃣ What is `strictNullChecks`?

Enforces explicit handling of `null` and `undefined`.

**Without it:**

```c
let name: string;
name = null; // allowed ❌
```

**With it:**

```c
let name: string;
name = null; // ❌ error
```

**Correct Way:**

```c
let name: string | null = null;
```

📌 Prevents most runtime crashes in TS apps.

# 3️⃣8️⃣ What are mapped types?

Mapped types create new types by transforming properties of an existing type.

**Example:**

```c
type ReadonlyUser = {
  readonly [K in keyof User]: User[K];
};
```

**Built-in mapped types:**

- `Readonly<T>`

- `Partial<T>`

- `Required<T>`

📌 Extremely powerful for type-level programming.

# 3️⃣9️⃣ What is a conditional type?

Conditional types allow types to depend on other types, similar to `if-else`.

**Example:**

```c
type IsString<T> = T extends string ? true : false;
```

**Usage:**

```c
type A = IsString<string>; // true
type B = IsString<number>; // false
```

📌 Used heavily in advanced libraries.

# 4️⃣0️⃣ What is `infer` keyword?

`infer` allows you to extract a type from within another type.

**Example:**

```c
type ReturnTypeOf<T> =
  T extends (...args: any[]) => infer R ? R : never;
```

**Usage:**

```c
type Result = ReturnTypeOf<() => number>; // number
```

📌 Powers utility types like:

- ReturnType

- Parameters

- Awaited
