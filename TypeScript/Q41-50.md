# 4️⃣1️⃣ What is a discriminated union?

A discriminated union is a union of object types that share a common literal property (called a discriminator).

**Why it exists**

It allows safe type narrowing without manual checks and enables exhaustive switch cases.

**Example**

```c
type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; size: number };

function area(shape: Shape) {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "square":
      return shape.size ** 2;
  }
}
```

**Benefits**

- Compile-time safety

- Cleaner logic than `instanceof`

- Prevents missing cases

📌 Heavily used in **Redux, state machines, API responses**

# 4️⃣2️⃣ Difference between `interface` and `class`?

| Interface            | Class                      |
| -------------------- | -------------------------- |
| Shape/contract only  | Blueprint + implementation |
| No runtime output    | Exists at runtime          |
| Cannot contain logic | Can contain logic          |
| Used for typing      | Used to create objects     |

**Example**

```c
interface User {
  name: string;
}

class Admin implements User {
  name = "Alice";
}
```

📌 Interfaces define what, classes define how.

# 4️⃣3️⃣ What are decorators?

Decorators are special functions that add metadata or behavior to:

- Classes

- Methods

- Properties

- Parameters

⚠️ They are experimental but widely used.

**Example (NestJS-style)**

```c
function Log(target: any) {
  console.log(target);
}

@Log
class UserService {}
```

**Common Use Cases**

-,Dependency Injection

- Validation

- Routing

- Logging

📌 Used heavily in **Angular & NestJS**

# 4️⃣4️⃣ How does TypeScript handle `async/await`?

TypeScript infers return types of `async` functions as `Promise<T>`.

**Example**

```c
async function getUser(): Promise<string> {
  return "Alice";
}
```

**Inferred Automatically**

```c
async function getCount() {
  return 5;
}
// inferred as Promise<number>
```

📌 TypeScript enforces await safety.

# 4️⃣5️⃣ What is a declaration file (`.d.ts`)?

A `.d.ts` file describes types for JavaScript code.

**Purpose**

- Provide type safety for JS libraries

- No runtime output

**Example**

```c
declare module "my-lib" {
  export function greet(name: string): string;
}
```

📌 Allows TypeScript to understand non-TS libraries

# 4️⃣6️⃣ Why is `unknown` preferred over `any`?

Because `unknown` enforces type checking before usage, preventing runtime crashes.

**Example**

```c
let data: unknown;

if (typeof data === "string") {
  console.log(data.toUpperCase());
}
```

**Key Difference**

- `any` → trust blindly

- `unknown` → verify first

📌 Interviewers expect you to prefer `unknown`.

# 4️⃣7️⃣ How to type Express request?

Express types are generic, allowing full request typing.

**Example**

```c
import { Request } from "express";

interface LoginBody {
  email: string;
  password: string;
}

const login = (req: Request<{}, {}, LoginBody>) => {
  req.body.email; // fully typed
};
```

📌 Prevents runtime API bugs.

# 4️⃣8️⃣ What is `esModuleInterop`?

Improves compatibility between:

- CommonJS (`require`)

- ES Modules (`import`)

**tsconfig.json**

```c
{
  "esModuleInterop": true
}
```

**Benefit**

```c
import express from "express"; // works correctly
```

📌 Mandatory for Node.js projects.

# 4️⃣9️⃣ Difference between `never` and `void`?

| never                        | void                  |
| ---------------------------- | --------------------- |
| Function never completes     | Function completes    |
| Throws error / infinite loop | Returns nothing       |
| Used for exhaustiveness      | Used for side effects |

**Example**

```c
function fail(): never {
  throw new Error("Error");
}

function log(): void {
  console.log("Hello");
}
```
