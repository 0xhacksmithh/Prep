# 21. What are Generics in TypeScript?

Generics allow you to create reusable, flexible, and type-safe code by letting you work with types as parameters, instead of hard-coding a specific type.

In simple terms:

```c
Generics = write code once, use it with many types, without losing type safety
```

### 🔹 Basic Example

```c
function identity<T>(arg: T): T {
  return arg;
}
```

**🔍 What’s happening?**

- `T` is a type variable (generic type parameter)

- `T` acts like a placeholder for the actual type

- The function:
  - Takes a value of type T

  - Returns the same type T

### 🔹 How TypeScript Uses Generics

**Example 1: Number**

```c
const num = identity<number>(10);
```

- `T` = `number`

- Input: `number`

- Output: `number`

**Example 2: String**

```c
const str = identity("hello");
```

TypeScript infers:

```c
T = string
```

✔ No need to explicitly write `<string>`

### 🔹 Why Not Use any?

**❌ Using any**

```c
function identityAny(arg: any): any {
  return arg;
}

const result = identityAny("hello");
result.toFixed(); // ❌ runtime error
```

**✅ Using Generics**

```c
const result = identity("hello");
result.toFixed(); // ❌ compile-time error
```

📌 Generics preserve type information, `any` destroys it.

### 🔹 Generics with Objects

```c
function wrap<T>(value: T): { value: T } {
  return { value };
}

const wrapped = wrap({ id: 1 });
```

Type inferred:

```c
{ value: { id: number } }
```

### 🔹 Generic Constraints (`extends`)

Sometimes you want to limit what types are allowed.

**Example:** Must have `length`

```c
function logLength<T extends { length: number }>(arg: T): T {
  console.log(arg.length);
  return arg;
}
```

**✔ Allowed:**

```c
logLength("hello");
logLength([1, 2, 3]);
```

❌ Not allowed:

```c
logLength(10);
```

### 🔹 Generics with Interfaces

```c
interface ApiResponse<T> {
  data: T;
  success: boolean;
}

const response: ApiResponse<User> = {
  data: { id: "1", name: "John" },
  success: true
};
```

🧠 Common in backend APIs.

### 🔹 Generics with Classes

```c
class Cache<T> {
  private store: T[] = [];

  add(item: T) {
    this.store.push(item);
  }

  getAll(): T[] {
    return this.store;
  }
}
```

**Usage:**

```c
const numberCache = new Cache<number>();
const userCache = new Cache<User>();
```

### 🔹 Multiple Generic Types

```c
function merge<A, B>(a: A, b: B): A & B {
  return { ...a, ...b };
}
```

Type result:

```c
const result = merge({ id: 1 }, { name: "John" });
// { id: number; name: string }
```

### 🔹 Default Generic Types

```c
interface ApiResult<T = string> {
  data: T;
}
```

**Usage:**

```c
ApiResult            // T = string
ApiResult<number>    // T = number
```

### 🔹 Real Backend Use Case

**Database Repository Pattern**

```c
class Repository<T> {
  findById(id: string): Promise<T | null> {
    // DB logic
    return Promise.resolve(null);
  }
}
```

```c
const userRepo = new Repository<User>();
```

- ✔ Strong typing
- ✔ Reusable logic
- ✔ No duplication

**🔥 Key Interview Takeaways**
| Concept | Why It Matters |
| ----------- | ---------------------------- |
| Reusability | One function for many types |
| Type safety | Compile-time error detection |
| Inference | Less code, more safety |
| Constraints | Controlled flexibility |

# 2️⃣2️⃣ What is `keyof`?

`keyof` creates a union of all property names (keys) of an object type.

**Example:**

```c
interface User {
  id: number;
  name: string;
  age: number;
}

type UserKeys = keyof User;
```

**Result:**

```c
type UserKeys = "id" | "name" | "age";
```

**Why `keyof` is important:**

- Enables type-safe property access

- Prevents invalid key usage

- Used heavily in generics and utility types

**Real-World Example:**

```c
function getValue<T>(obj: T, key: keyof T) {
  return obj[key];
}

getValue(user, "name"); // ✅
getValue(user, "email"); // ❌ compile-time error
```

📌 `keyof` ensures only valid keys are allowed.

# 2️⃣3️⃣ What is typeof?

`typeof` in TypeScript extracts the type of a variable or value.

**Example:**

```c
let x = 10;
type X = typeof x;
```

**Result:**

```c
type X = number;
```

**Difference from JavaScript `typeof`:**
| JavaScript | TypeScript |
| -------------- | -------------- |
| Runtime | Compile-time |
| Returns string | Returns a type |

**Real-World Example:**

```c
const config = {
  host: "localhost",
  port: 3000,
};

type Config = typeof config;
```

📌 Avoids duplicating types → **Single source of truth**

# 2️⃣4️⃣ What are utility types?

Utility types are built-in generic helpers that transform existing types into new ones without rewriting them.

**Common Utility Types:**

- `Partial<T>`

- `Required<T>`

- `Readonly<T>`

- `Pick<T, K>`

- `Omit<T, K>`

📌 Utility types improve:

- Reusability

- Maintainability

- Type safety

# 2️⃣5️⃣ Explain `Partial<T>`

`Partial<T>` makes all properties optional.

**Example:**

```c
type User = {
  id: number;
  name: string;
  age: number;
};

type PartialUser = Partial<User>;
```

**Result:**

```c
{
  id?: number;
  name?: string;
  age?: number;
}
```

**Real-World Use Case:**

- PATCH APIs

- Update operations

- Form inputs

```c
function updateUser(data: Partial<User>) {}
```

📌 Allows flexible updates without breaking type safety.

# 2️⃣6️⃣ Explain `Pick<T, K>`

`Pick<T, K>` selects specific properties from a type.

**Example:**

```c
type UserName = Pick<User, "name">;
```

**Result:**

```c
{
  name: string;
}
```

**Real-World Use Case:**

- API responses

- DTOs

- Security (avoid leaking fields)

```c
type PublicUser = Pick<User, "id" | "name">;
```

📌 Prevents over-exposing data.

# 2️⃣7️⃣ Explain `Omit<T, K>`

`Omit<T, K>` removes specific properties from a type.

**Example:**

```c
type UserWithoutAge = Omit<User, "age">;
```

**Result:**

```c
{
  id: number;
  name: string;
}
```

**Real-World Use Case:**

```c
type UserWithoutPassword = Omit<User, "password">;
```

📌 Very common in backend APIs for security.

# 2️⃣8️⃣ What is `as` keyword?

The `as` keyword is used for type assertion—telling TypeScript

`“Trust me, I know the type.”`

**Example:**

```c
let value = "hello" as string;
```

**DOM Example:**

```c
const input = document.getElementById("email") as HTMLInputElement;
```

**Important:**

- No runtime conversion

- Only affects TypeScript compiler

⚠️ Overusing `as` can hide real bugs

📌 Prefer type guards when possible.

# 2️⃣9️⃣ What is strict mode?

Strict mode enables maximum type safety in TypeScript.

Enabled in `tsconfig.json`:

```c
{
  "strict": true
}
```

**Strict mode includes:**

- strictNullChecks

- noImplicitAny

- strictFunctionTypes

- strictPropertyInitialization

**Example:**

```c
let name: string;
name = null; // ❌ Error
```

📌 Recommended for all production apps

# 3️⃣0️⃣ What is non-null assertion (`!`)?

The non-null assertion operator tells TypeScript that a value is definitely not null or undefined.

**Example:**

```c
user!.name
```

**Meaning:**

“I guarantee this value exists”

**Common Use Case:**

```c
const input = document.getElementById("email")!;
input.value = "test";
```

**Risk:**

- Compiler trusts you

- Runtime error if value is actually null

⚠️ Use sparingly and only when 100% sure
